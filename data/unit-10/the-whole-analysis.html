Unit 10 • Lesson 6

The Whole Analysis

Overview

Load, clean, join, summarise, report — in one function, from files.

Intermediate 20–25 min
← Previous Unit 10 test

What You Will Learn in This Lesson

By the end of this lesson, you will be able to:

  • Put the steps from this course in the order that keeps each one correct.
  • Clean types and missing values before joining, not after.
  • Check row counts between steps, so a silent loss shows up.
  • Return a result a reader can use, from two raw files.

Why This Matters

Every unit so far taught one step on its own, on data that arrived ready for it. Real work is the chain, and the chain fails at the joints: an id kept as "007" in one file meets "7" in another and matches nothing, a missing marker survives into a mean. Doing the whole thing once, with checks between the steps, is what turns the separate skills into an analysis.

Step 1: The order matters

The steps are the ones you already know. What is new is that each one depends on the one before it being right.

1

Read, then look

Read each file and check its shape and dtypes before doing anything else. A score column that comes back as object is the first sign of a missing marker, and it is far cheaper to notice here than after a join.

import io
import pandas as pd

scores = pd.read_csv(io.StringIO("id,score\n1,90\n2,n/a\n3,70\n"))
print(scores.shape)
print(scores.dtypes)
2

Clean before you join

Convert types and deal with missing values on each table while it is still small and on its own. After a merge the bad rows are mixed in with good ones from the other file, and it is much harder to say which table they came from.

import io
import pandas as pd

scores = pd.read_csv(io.StringIO("id,score\n1,90\n2,n/a\n3,70\n"))
scores["score"] = pd.to_numeric(scores["score"], errors="coerce")
print(scores.dtypes)
print(int(scores["score"].isna().sum()), "missing")
3

Then join, then summarise

Merge on the key, group, and take the summary. Rounding comes last, at the moment the number is shown, so no step downstream computes with a rounded value.

import io
import pandas as pd

people = pd.read_csv(io.StringIO("id,team\n1,red\n2,red\n3,blue\n"))
scores = pd.read_csv(io.StringIO("id,score\n1,90\n2,80\n3,70\n"))
out = pd.merge(people, scores, on="id")
print(out.groupby("team")["score"].mean().round(1))

Step 2: Check between the steps

Each step can lose rows without raising anything. A check is one line that prints what you expect to be true.

1

How much did cleaning drop?

Count before and after. If a third of the rows vanished at the cleaning step, that belongs in the write-up, not in a surprise later.

import pandas as pd

df = pd.DataFrame({"id": [1, 2, 3], "score": ["90", "n/a", "70"]})
df["score"] = pd.to_numeric(df["score"], errors="coerce")
kept = df.dropna(subset=["score"])
print(len(df) - len(kept), "dropped of", len(df))
2

Did the join keep what it should?

An inner join drops every row whose key has no partner. Compare the row count after the merge with the table you expected it to match.

import pandas as pd

people = pd.DataFrame({"id": [1, 2, 3], "team": ["red", "red", "blue"]})
scores = pd.DataFrame({"id": [1, 2, 4], "score": [90.0, 80.0, 70.0]})
out = pd.merge(people, scores, on="id")
print("people:", len(people), "joined:", len(out))

Key idea: The checks are not the analysis, and they do not need to stay in the final function as prints. What matters is that you ran them and know the answers, because "how many rows did that rest on" is the first question anyone asks.

Step 3: One function, two files

Wrapping the chain in a function with the file paths as arguments makes it rerunnable, which is the point: next term's files should go through the same steps without anybody copying code.

1

Paths in, answer out

The function reads, cleans, joins and summarises, and returns plain Python values. A caller does not need to know pandas was involved.

import pandas as pd

open("people.csv", "w").write("id,team\n1,red\n2,blue\n")
open("scores.csv", "w").write("id,score\n1,90\n2,70\n")

def best_team(people_path, scores_path):
    people = pd.read_csv(people_path)
    scores = pd.read_csv(scores_path)
    means = pd.merge(people, scores, on="id").groupby("team")["score"].mean()
    return str(means.idxmax())

print(best_team("people.csv", "scores.csv"))
2

The same function on different data

Run it again on a second pair of files. If the answer changes when the data does and nothing else had to change, the analysis is finished.

import pandas as pd

def best_team(people_path, scores_path):
    people = pd.read_csv(people_path)
    scores = pd.read_csv(scores_path)
    means = pd.merge(people, scores, on="id").groupby("team")["score"].mean()
    return str(means.idxmax())

open("people.csv", "w").write("id,team\n1,red\n2,blue\n")
open("scores.csv", "w").write("id,score\n1,40\n2,95\n")
print(best_team("people.csv", "scores.csv"))

Step 4: When to Use It

A question that needs several files

Read, clean each table, join, summarise, report — in that order.

report("people.csv", "scores.csv")

Analyses you will rerun

A function over the file paths, with checks between the steps, handles next term’s data unchanged.

When Not to Use It

Do not skip the checks between steps because the final number looks plausible. Rows lost at a join or a clean are exactly what makes a plausible number wrong.
