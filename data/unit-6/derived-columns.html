Unit 6 • Lesson 3

Derived Columns

Overview

The column that answers your question usually is not in the file.

Intermediate 20–25 min
← Previous Next: apply, and When Not To

What You Will Learn in This Lesson

By the end of this lesson, you will be able to:

  • Build a column from arithmetic between other columns.
  • Divide a column by one of its own summaries.
  • Use assign when you want to keep a chain going.
  • Say why a rate is usually more comparable than a total.

Why This Matters

Files hold what was recorded; questions are about rates, shares and differences. "Which region sells most" and "which region sells most per head" are different questions with different answers, and only one of them is in the file.

Step 1: Arithmetic between columns

Columns combine row by row, so a rate, a total or a difference is one expression.

1

Two columns in, one out

The alignment is by index, so the rows always line up with themselves.

import pandas as pd

df = pd.DataFrame({"sales": [100.0, 90.0], "people": [4, 3]})
df["per_person"] = df["sales"] / df["people"]
print(df)
2

A column against its own total

Dividing a column by its sum broadcasts the single total across every row, giving each row's share.

import pandas as pd

df = pd.DataFrame({"amount": [25.0, 75.0]})
df["share"] = df["amount"] / df["amount"].sum() * 100
print(df)
3

Why the rate is the fairer comparison

The biggest total is often just the biggest region. Per head, the ranking can reverse entirely — and that reversal is usually the finding.

import pandas as pd

df = pd.DataFrame({"region": ["A", "B"], "sales": [1000.0, 300.0], "people": [500, 50]})
df["per_person"] = df["sales"] / df["people"]
print(df)

Step 2: assign keeps the chain going

assign returns a new table with the column added, which is useful when you are building a pipeline rather than editing a variable.

1

One expression, several steps

Each step hands a table to the next, and nothing in between needs a name. It also leaves the original alone, which the plain assignment form does not.

import pandas as pd

df = pd.DataFrame({"sales": [1000.0, 300.0], "people": [500, 50]})

result = (df
          .assign(per_person=lambda d: d["sales"] / d["people"])
          .sort_values("per_person", ascending=False))
print(result)
print(list(df.columns))   # untouched

The lambda receives the table as it is at that point in the chain, which is what lets a later assign use a column an earlier one just made.

Step 3: When to Use It

Arithmetic across columns

Ratios, differences and percentages are one vectorised expression.

df["gap"] = df["target"] - df["score"]

Labels from a condition

np.where or a mapping turns a number or code into the category a reader understands.

When Not to Use It

Do not derive a column with a Python loop over rows. A vectorised expression is shorter, faster, and handles missing values consistently.
