What Data Analysis Actually Is

Overview

Four steps that turn a file of rows into an answer you can defend.

Beginner 20–25 min
← Previous Next: Rows and Columns with Lists

What You Will Learn in This Lesson

By the end of this lesson, you will be able to:

  • Name the four steps every analysis goes through, in order.
  • Turn a vague goal into a question a table can answer.
  • Compute an answer from the data rather than reading it off and typing it.
  • Say why the cleaning step is where most of the time and most of the mistakes go.

Why This Matters

Every tool in this course — the csv module, numpy, pandas — is a faster way of doing one of four steps. Knowing the steps first is what stops the tools feeling like a pile of unrelated functions, and it is what lets you notice when an analysis skipped one. The most common bad result is not a wrong calculation; it is a correct calculation over data nobody looked at.

Step 1: The shape of the work

Every analysis, from a class spreadsheet to a national survey, makes the same four moves. The tools change; the moves do not.

1

Get, clean, summarise, explain

Get the data into your program. Clean it until it means what you think it means. Summarise it into a few numbers. Explain what those numbers say — and what they do not. This unit covers getting and summarising with plain Python; unit 2 is entirely about cleaning.

rows = [
    ["Ada", 92],
    ["Grace", 88],
    ["Alan", 79],
]

# Get: the rows are here.
# Summarise: how many, and the best score.
print("students:", len(rows))
print("best:", max(r[1] for r in rows))
2

Where the time actually goes

The summary is often three lines. Getting the data fit to summarise — finding the blank score, the name typed twice, the number stored as text — is most of the job. It is also where mistakes hide, because nothing raises when a column is dirty; the average simply comes out wrong.

scores = ["92", "88", ""]

# One blank value, and a sum over the column fails outright.
# Worse cases do not fail at all -- that is unit 2.
print(len(scores), "values, one of them empty:", scores.count(""))

Step 2: An answer needs a question first

A table on its own says nothing. It answers questions, and only the ones precise enough to be computed.

1

Vague goals and computable questions

"Is this class doing well?" cannot be computed until you decide what well means. "What is the average score, and how many students are below 60?" can. Writing the question down first is also what stops you fishing — a table always contains some pattern if you look long enough.

scores = [92, 88, 79, 55]

print("average:", sum(scores) / len(scores))
print("below 60:", len([s for s in scores if s < 60]))
2

The question decides the summary

"Who scored highest?" wants max. "How spread out are the scores?" wants the smallest and largest together. "How many passed?" wants a count. Choosing the summary is the second half of asking the question.

scores = [92, 88, 79, 55]

print("highest:", max(scores))
print("range:", min(scores), "to", max(scores))
print("passed:", len([s for s in scores if s >= 60]))

Step 3: Compute it, do not copy it

The single habit that separates analysis code from a calculator: the answer is derived from the data every time the code runs.

1

A typed answer is right once

print(3) is correct today. Add a fourth student and it is silently wrong, and nothing in the code tells you. print(len(rows)) is correct for every version of the data.

rows = [["Ada", 92], ["Grace", 88], ["Alan", 79], ["Katherine", 99]]

print(3)          # stale the moment the data changed
print(len(rows))  # still right
2

Reading a column out of rows

To take the largest score you need the scores on their own. A generator over the rows pulls one position out of each — the same idea the next lesson calls a column.

rows = [["Ada", 92], ["Grace", 88], ["Alan", 79]]

print(max(r[1] for r in rows))
print(min(r[1] for r in rows))

Key idea: Later, pandas will do df["score"].max(). It is the same move: select a column, then summarise it. Nothing in this unit is thrown away.

Predict, then check: A boundary can change the answer

Before you run this, predict both lists. Does a score of exactly 60 count as a pass?

scores = [59, 60, 61]
print([score for score in scores if score > 60])
print([score for score in scores if score >= 60])
Show the output and explanation 
[61]
[60, 61]

The first condition excludes 60; the second includes it. Translate “60 or more” into >= before choosing a function. A calculation can run perfectly and still answer the wrong question.

Try one change: Change the passing threshold to 61. Predict which list becomes empty before running again.

Step 4: When to Use It

A question with a computable answer

When you can say what number would settle it — a count, an average, a highest — the four steps apply directly.

print(len([s for s in scores if s < 60]))

Before you trust a number someone quotes

Walking back through get, clean, summarise and explain is how you check someone else’s figure as well as your own.

When Not to Use It

Do not start summarising before you have written the question down. A table always offers some pattern, and a pattern found by browsing is not a finding.
