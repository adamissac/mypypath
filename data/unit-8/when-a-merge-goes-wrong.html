When a Merge Goes Wrong

Duplicate keys multiply rows, and mismatched types match nothing.

Unit 8 · Combining Tables

  • 1. Stacking Tables with concat

  • 3. When a Merge Goes Wrong
  • 4. Wide to Long with melt
  • 5. Long to Wide with pivot

What You Will Learn in This Lesson

  • Predict the row count of a join before running it.
  • Explain why a duplicate key multiplies rows.
  • Spot a type mismatch that makes a join match nothing.
  • Have pandas check your assumption with validate.

Why This Matters

These are the two failures that produce a wrong number rather than an error. A duplicated key inflates a total silently; a type mismatch empties the result silently. Both are cheap to check for and expensive to discover later, which is the whole argument of this lesson.

A key that repeats multiplies

Every matching row on the left pairs with every matching row on the right. Two and two make four, not two.

The multiplication

One person, two score rows, two output rows. Sum the scores now and the person counts twice.

import pandas as pd

people = pd.DataFrame({"id": [1], "name": ["Ada"]})
scores = pd.DataFrame({"id": [1, 1], "score": [90, 80]})
out = pd.merge(people, scores, on="id")
print(out)
print(len(people), "x duplicated key ->", len(out), "rows")

Check the key before you join

One line, and it answers the question the row count would otherwise raise afterwards.

import pandas as pd

scores = pd.DataFrame({"id": [1, 1, 2], "score": [90, 80, 70]})
print("duplicated keys:", int(scores["id"].duplicated().sum()))
print(scores["id"].value_counts())

Let pandas hold you to it

validate states the relationship you believe you have, and raises when the data disagrees — instead of silently multiplying.

import pandas as pd

people = pd.DataFrame({"id": [1], "name": ["Ada"]})
scores = pd.DataFrame({"id": [1, 1], "score": [90, 80]})
try:
    pd.merge(people, scores, on="id", validate="one_to_one")
except Exception as exc:
    print(type(exc).__name__ + ":", exc)

"one_to_one", "one_to_many" and "many_to_one" are the useful three. Writing down which one you expect is also documentation for the next reader.

Types have to match too

An id read as a number in one file and as text in another matches nothing, and the merge succeeds with an empty result.

The quietest failure in the unit

1 and "1" are different keys. No error, no warning, no rows.

import pandas as pd

a = pd.DataFrame({"id": ["1"], "name": ["Ada"]})
b = pd.DataFrame({"id": [1], "score": [90]})
print(len(pd.merge(a, b, on="id")), "rows")
print(a["id"].dtype, "vs", b["id"].dtype)

Compare the dtypes first

The fix is to make both sides the same type before joining. Converting only one side leaves the mismatch where it was.

import pandas as pd

a = pd.DataFrame({"id": ["1"], "name": ["Ada"]})
b = pd.DataFrame({"id": [1], "score": [90]})

a2, b2 = a.copy(), b.copy()
a2["id"] = a2["id"].astype(str)
b2["id"] = b2["id"].astype(str)
print(len(pd.merge(a2, b2, on="id")), "rows")

Whitespace does the same thing

"1 " and "1" are also different keys. Stripping both sides is part of the same preparation.

import pandas as pd

a = pd.DataFrame({"id": ["1 "], "name": ["Ada"]})
b = pd.DataFrame({"id": ["1"], "score": [90]})
print(len(pd.merge(a, b, on="id")), "rows")

a["id"] = a["id"].str.strip()
print(len(pd.merge(a, b, on="id")), "rows")
